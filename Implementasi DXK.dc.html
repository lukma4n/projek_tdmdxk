Bagian 01

Arsitektur Sistem

DXK adalah aplikasi internal cabang berbasis LAN. Karakter utamanya: bukan sistem transaksi — mayoritas data masuk lewat import snapshot berkala dari sistem induk AHM, hanya follow-up & opname yang diinput manual. Ini menyederhanakan arsitektur secara signifikan.

Browser Klien
PC staf cabang
Single Page App (React + Tailwind v4). Tema light/dark per user di localStorage. Desktop-first ≥1280px.
Backend API
REST / JSON
Server tunggal di kantor cabang. Auth (session/JWT), RBAC per menu, business logic, Import Engine (parser Excel/DOCX/PDF), penjadwal backup.
Database
MySQL / PostgreSQL
Penyimpanan relasional. File backup (.sql / dump) disimpan di disk lokal server; foto handover di folder storage.
Prinsip kunci
  • Data master = read-only hasil import; jangan diedit manual
  • Setiap import destruktif wajib buat backup otomatis dulu
  • Akses ditentukan per menuKey × role
  • Semua waktu pakai timezone server cabang (WIB)
Mengapa sederhana?

Karena tidak ada transaksi real-time multi-user yang rumit, tidak perlu message queue, microservices, atau caching layer. Monolith (satu backend + satu DB) sudah lebih dari cukup dan jauh lebih murah dirawat tim kecil.

Aturan keamanan import

  • Validasi header kolom sebelum proses; tolak jika tidak cocok
  • Transaksi DB — semua baris sukses atau rollback total
